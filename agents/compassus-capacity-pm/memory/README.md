# Project memory — full depth

`CLAUDE.md` at the repo root is the short memory every session loads. This folder is the long
memory: everything learned and decided in the vendor-scoring work, at full depth, so a new session
can pick up any thread without re-deriving it.

| File | What it holds |
|---|---|
| `session-2026-09-vendor-scoring.md` | The full record of the vendor-scoring session: every decision, the user's feedback and what it changed, what was tried and rejected, engineering lessons, verification procedure, open items |
| `project-context-inventory.md` | The initiative at full depth: 25 load-bearing facts, 46-term vocabulary, the scope taxonomy, what our own thinking says a good solution does, known traps, the source-of-truth map for every topic, and the gaps the repo cannot fill |
| `questionnaire-rubric-deep-read.md` | The questionnaire's structure and the two rubric versions compared; vendor archetypes and cross-question patterns; the voice; the thirteen things the rubric deliberately does not do |
| `handoff-pack-design.md` | Why the handoff pack is shaped the way it is: the two findings that drove it, the file set, the protocol, the guardrails, the risks and their mitigations |

The handoff pack itself is at `../vendor-evaluation/handoff/`. It is the operational form of this
knowledge; these files are the reasoning behind it.
